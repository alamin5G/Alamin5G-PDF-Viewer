# v1.0.13 - Critical OOM Crash Fix Summary

## 🚨 Critical Issue (v1.0.12)
**Production crash in SokalSondhaDoa app:**
- **PDF**: 285 pages (`sunnat_1000.pdf`)
- **Crash Point**: Page 276 rendering
- **Error**: `onServiceDisconnected (crash or killed by oom)`
- **Root Cause**: `renderAllPages()` rendered ALL 285 pages simultaneously
- **Memory Usage**: ~1.97 GB (far exceeds Android app limits)

## ✅ Solution (v1.0.13)
**Implemented Lazy Loading / Virtual Scrolling:**

### New Architecture
1. **initializePageOffsets()**: Calculate positions for ALL pages (lightweight, no bitmaps)
2. **renderVisiblePages()**: Render only visible pages + 2-page buffer
3. **calculateVisiblePages()**: Detect which pages are on-screen
4. **renderSinglePage()**: Render individual page to cache
5. **continuousPageCache**: LinkedHashMap with LRU eviction (max 10 pages)

### Memory Optimization
- **Before**: 285 pages × 6.9 MB = ~1.97 GB → **CRASH**
- **After**: 10 pages × 6.9 MB = ~70 MB → **Smooth**
- **Reduction**: **95% less memory usage**

### Code Changes
**File**: `PDFView.java`
- Added `continuousPageCache` (LinkedHashMap with LRU)
- Added `visibleStartPage`, `visibleEndPage` tracking
- Replaced `renderAllPages()` with `renderVisiblePages()`
- Updated `onDraw()` to use cache instead of ArrayList
- Updated `onScroll()` to trigger lazy loading
- Updated `zoomCenteredTo()` to re-render visible pages only
- Updated `onSizeChanged()` to use lazy initialization
